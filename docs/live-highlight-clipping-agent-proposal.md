# 直播高光短视频剪辑智能体建设与执行方案

> 基于 HyperFrames 的直播内容理解、亮点筛选与自动化视频生产  
> 适用项目：银发歌唱教育 AI 智能体及其他直播内容场景  
> 文档版本：1.0｜日期：2026年11月

## 一、方案摘要

本方案建设一个可执行的直播高光短视频智能体。用户上传直播录像后，系统完成媒体检查、音视频转写、内容分段、焦点识别、高光评分、候选片段审核、字幕与视觉包装、HyperFrames 渲染及成片下载。目标不是把直播机械地切成若干段，而是找到具有明确主题、信息价值、情绪或互动亮点，并且脱离直播上下文仍能看懂的片段。

产品由智能体工作台（前端）、业务 API 与任务编排后端、媒体分析服务、对象存储/数据库、HyperFrames 项目生成与渲染服务构成。模型给出候选与依据，规则负责安全边界和质量门槛，用户可在时间轴上复核、改起止点、改标题和字幕，然后确认渲染。

## 二、产品目标与设计原则

- **高光优先：**只推荐有明确亮点的内容，不以固定间隔切段。
- **可解释：**每个推荐片段展示起止时间、摘要、亮点类型、评分依据及转写证据。
- **人机协作：**候选由 AI 生成，用户可以接受、排除、合并、拆分、调整边界；未经确认不自动发布。
- **适合银发歌唱教育：**优先发现教师示范、学员进步、唱法纠正前后对比、易懂技巧、答疑互动、集体共鸣和课堂成果。
- **可复现可编辑：**HyperFrames 使用 HTML/CSS/JavaScript 时间线组合，保留项目文件与素材引用，便于重新渲染。
- **隐私与版权：**上传授权、访问控制、保留期限、音乐授权、肖像与声音授权均纳入流程。

## 三、智能体页面

### 3.1 页面信息架构

| 页面/区域 | 主要内容 | 关键操作 |
|---|---|---|
| 登录与项目首页 | 项目列表、近期任务、配额与状态 | 新建剪辑任务、查看历史、管理成员 |
| 新建任务/上传 | 拖拽上传、文件信息、场景、平台、目标时长、画幅、字幕语言 | 上传、取消、原声选择、版权/授权确认 |
| 智能体分析工作台 | 进度、直播摘要、章节时间线、转写文本、高光卡片、评分与理由 | 查看证据、重跑、反馈、筛选标签 |
| 切片编辑器 | 视频预览、波形/时间轴、入点出点、字幕、标题、封面、音乐、模板 | 调整边界、修改字幕、保存草稿、确认渲染 |
| 模板与品牌设置 | 品牌色、字体、角标、片头片尾海报、字幕样式、音乐曲库 | 上传资产、预览与管理模板 |
| 渲染与交付 | 渲染队列、状态、输出规格、预览与文件列表 | 下载 MP4/封面、重新渲染、删除 |
| 设置与合规 | 成员权限、存储期限、删除策略、审计记录 | 设置保留期、撤销访问、申请删除 |

### 3.2 工作台交互流程

1. 用户新建项目并上传录像；页面显示上传进度、校验结果和分析状态。
2. 分析完成后呈现章节概览与候选高光。候选卡显示缩略图、时间范围、标题建议、摘要、类型、总分及分项分数。
3. 点击候选可播放时间码对应的视频并查看转写证据。证据不足、音频不清或画面缺失时明确提示，不虚构内容。
4. 用户挑选候选，设定竖屏/横屏、目标时长、字幕样式、标题和音乐；支持批量套用模板。
5. 预览后确认渲染。成功后提供 MP4、封面和可选项目包下载；失败显示错误原因和重试入口。

任务状态建议统一为：`queued`、`uploading`、`analyzing`、`review_required`、`rendering`、`succeeded`、`failed`、`cancelled`。长任务通过 SSE 或轮询显示进度；网络中断后可恢复查看。错误分类包括格式不支持、文件损坏、无可用音轨、转写失败、素材缺失、HyperFrames 检查失败和渲染超时。

## 四、系统架构与职责边界

```text
浏览器前端（工作台 / 编辑器）
  ├─ 业务 API：身份、项目、上传、任务、候选、编辑、渲染、下载
  └─ 任务编排服务（队列 / 状态机）
       ├─ 媒体预处理：FFmpeg 探测、抽音频、代理视频、关键帧
       ├─ 内容理解：ASR 转写、说话人/章节、文本与视听事件分析
       ├─ 高光决策：候选生成、评分、去重、时长与上下文校验
       ├─ 剪辑计划：时间码、字幕、标题、画幅适配、模板参数
       └─ HyperFrames 生产器：生成项目 → check → 预览/抽帧审核 → render
存储：关系数据库 + 对象存储（原片、代理、缩略图、转写、项目、成片）
```

HyperFrames 是 HTML 原生、可逐帧确定性渲染的视频合成/渲染引擎，负责把已选片段、图形、字幕、音乐和动画按时间线渲染。直播语义理解、ASR、亮点判断、素材权限、用户审核和任务管理属于上游业务能力，不能假设 HyperFrames 自己会判断高光。

## 五、前端实施设计

推荐 React 或 Vue。核心组件：分片/断点续传上传器、任务状态面板、候选高光卡片、带时间码播放器、波形与剪辑边界编辑器、字幕编辑表格、模板预览器、渲染任务列表和下载组件。

- 所有业务请求带登录态；项目和任务必须由服务端校验权限。
- 大文件采用预签名 URL，避免通过业务服务器转发；耗时操作返回 `task_id`，通过事件流或轮询取进度。
- 时间统一使用原片时间轴的秒（小数），展示为 `HH:MM:SS.mmm`；裁切服务处理关键帧和编码误差。
- 编辑提交差异配置，保留 AI 原始结果，支持草稿版本及撤销/重做。
- 使用 `Idempotency-Key` 防止重复创建任务；支持可取消/重试策略。

## 六、后端 API 设计（建议 REST API v1）

基础路径：`/api/v1`。统一响应：`{"data":...,"error":null,"request_id":"..."}`。错误结构含 `code`、`message` 和可安全展示的 `details`。鉴权采用会话或 OAuth/JWT；所有对象按租户/项目做服务端权限隔离。

| 方法与路径 | 用途与请求要点 | 成功响应 |
|---|---|---|
| `POST /projects` | 创建项目；`name, scene, default_template_id` | 201：project |
| `GET /projects` | 当前用户项目；支持 cursor/limit | 200：items、next_cursor |
| `POST /media/uploads` | 申请上传；`project_id, filename, size_bytes, mime_type, checksum` | 201：media_id、upload_url、parts、expires_at |
| `POST /media/{media_id}/complete` | 完成上传并触发媒体探测、校验哈希 | 202：media、probe_task_id |
| `GET /media/{media_id}` | 查询时长、分辨率、音轨与处理状态 | 200：media metadata |
| `POST /projects/{project_id}/clip-jobs` | 创建分析任务；媒体、场景、语言、画幅、时长范围、数量、标签、选项 | 202：job_id、status |
| `GET /jobs/{job_id}` | 获取状态、阶段、百分比、错误与时间 | 200：job status |
| `GET /jobs/{job_id}/events` | SSE 进度事件：stage、progress、message、updated_at | `text/event-stream` |
| `POST /jobs/{job_id}/cancel` | 取消可取消的分析/渲染任务 | 202：status |
| `GET /jobs/{job_id}/transcript` | 带时间码的转写、说话人、置信度 | 200：segments[] |
| `GET /jobs/{job_id}/highlights` | 按分数/时间/类别查询候选高光 | 200：items[] |
| `PATCH /highlights/{highlight_id}` | 修改标题、标签、时间边界、审核状态；保存版本 | 200：更新后候选 |
| `POST /highlights/{highlight_id}/feedback` | 接受/拒绝和原因反馈；不得自动视为训练数据 | 202：feedback_id |
| `POST /projects/{project_id}/renders` | 创建渲染；选中候选、模板、格式、字幕、音乐、海报、原声选项 | 202：render_id、status |
| `GET /renders/{render_id}` | 查询进度、check 结果、输出规格、错误 | 200：render status |
| `GET /renders/{render_id}/outputs` | 获取成片、封面、字幕、项目包的短时下载链接 | 200：outputs[] |
| `POST /renders/{render_id}/retry` | 重新排队可重试的渲染失败 | 202：new attempt |
| `GET /templates` | 项目可用包装模板 | 200：templates[] |
| `POST /assets` | 上传海报、音乐、字体或图形并记录授权 | 201：asset |
| `DELETE /media/{media_id}` | 删除原片及衍生资产，异步执行 | 202：deletion job |

## 七、后端服务与高光评分

### 服务模块

- **媒体服务：**文件探测、校验、代理视频、抽取音频、关键帧与波形；原片只读保留。
- **转写服务：**输出带词级或句级时间戳的文本、语言、置信度；支持人工纠错。
- **内容理解服务：**章节切分、主题归纳、问答/示范/总结事件识别；情绪仅作为弱信号。
- **高光排序服务：**结合语义价值、信息完整性、独立观看性、音视频质量、互动信号、重复度与风险项。
- **剪辑计划服务：**按句界/静音边界调整候选起止，避免截断问题、回答、歌曲乐句或关键动作。
- **HyperFrames 生产服务：**由受控模板和 JSON 参数生成项目，执行 CLI 检查、预览/抽帧审核与渲染；记录版本和素材哈希。
- **任务队列：**幂等、可重试，设置并发、超时、优先级和失败队列。

初期可采用可解释权重：主题/知识价值 30%、表达清晰与信息完整 25%、独立成片能力 20%、互动或情绪变化 10%、画面/声音质量 10%、新颖性 5%。重复片段、严重噪声、语义不完整、授权不明为扣分或阻断条件。按人工标注集评估命中率后再调权重；歌唱示范场景可配置不同权重。分数用于排序，不代表传播效果保证。

## 八、HyperFrames 视频包装与首尾帧要求

### 画面与模板

默认社交平台竖屏 9:16、1080×1920、30fps；另支持 16:9 与 1:1。可包含主体直播视频、动态字幕、标题、重点词强调、讲师/课程角标、品牌图形、转场/轻动画、可选背景音乐及封面海报。画面放在安全区域，字号照顾中老年观看者；不得遮挡口型、乐器或教学动作。

### 片头、片尾与首尾帧一致（硬性验收）

- 首帧 t=0：完整静态海报，不加随机或依赖实时网络的内容。
- 片头：海报停留约 0.5–1 秒，以淡出、缩放或遮罩轻动画进入主体。
- 主体：高光视频、逐句字幕、必要的强调动画和辅助图形。
- 片尾：主体结束后回到与 t=0 **完全相同**的海报视觉状态，停留约 0.8–1.5 秒。
- 实现：复用同一静态海报素材/图层和相同 CSS 状态，不另造一张“看起来差不多”的图。片头和片尾的动画结束态都落在这个海报状态。
- 音频：片头片尾可配轻音乐并淡入淡出；视觉帧一致是强制项，音频波形不要求一致。音乐须有授权，讲解/演唱期间自动降低或关闭 BGM。
- 验收：FFmpeg 抽取首帧与末帧像素比较；如编码差异，设容差并人工检查构图、文字、颜色和布局一致。

### 动画、图画、字幕、音乐

- 字幕逐句同步、简体中文、易读；关键词可强调但不整屏跳动，支持 SRT/VTT 导出。
- 动画由时间轴驱动、可确定性 seek；保持适度，避免眩晕。
- 图形可使用品牌图标、乐谱符号、气息/节奏提示；不得生成与讲解不符的乐理信息。
- 优先保留教师讲解、歌唱示范原声；BGM 自动 ducking。音乐资产记录来源、许可证、用途与有效期。
- 封面基于同一海报模板导出静态图，标题简短易读，不夸大视频内容。

### HyperFrames 工程约定

项目保存根组合、场景组合、素材与渲染参数。时间元素声明 `class="clip"`、`data-start`、`data-duration`；场景注册暂停时间线。视频音频按时间线配置，音乐用独立 audio 轨道，素材用相对路径。渲染前执行 `npx hyperframes check --json`，处理错误并审查警告；先预览和抽帧再批量生产。禁止依赖网络请求、系统当前时间、非固定随机数或不可 seek 的动画。

## 十、合规与质量控制

- 上传时确认用户有权处理直播录像、肖像/声音及背景音乐；观众发言和个人信息按最小化原则处理。
- 下载链接短时有效；租户隔离对象存储；传输与存储加密；提供删除入口和可追踪状态。
- 隐私泄露、敏感内容、明显侵权片段可要求人工审核或禁止导出。
- 模型结果保留证据和置信度；不得把自动摘要伪装成逐字原话；低置信字幕提示人工校对。
- 质量检查：可播放、时长/画幅正确、音画同步、字幕不截断、无异常黑帧、首尾海报一致、音乐授权记录完整。

## 十一、分阶段实施与验收

| 阶段 | 交付范围 | 建议验收 |
|---|---|---|
| 一期：可用原型 | 单条直播上传、ASR、候选高光、人工挑选、一个 HyperFrames 竖屏模板、MP4 | 任务可追踪；候选有证据；人工可改边界；成片可播放；首尾海报同源一致 |
| 二期：编辑包装 | 时间线、字幕校正、封面、片头片尾动画、音乐、多时长/画幅 | 可保存草稿与重渲染；字幕和配乐可控；首尾帧自动比对 |
| 三期：批量优化 | 批量任务、模板管理、反馈分析、质量报表、队列扩容 | 可观测成功率/耗时/成本；错误可重试；高光质量人工抽检 |
| 四期：生产运营 | 多租户、审计、权限、保留策略、更多场景 | 安全及授权流程审查通过；删除/审计可追踪；有故障恢复预案 |

## 十二、MVP 默认配置

- 单次处理一条 MP4/MOV；先支持中文普通话。
- 每条直播最多推荐 8 个候选，默认 20–60 秒；可选择 15/30/60 秒目标。
- 默认 9:16、1080×1920、30fps；原声优先，BGM 默认关闭或极低音量，仅使用授权曲库。
- 固定品牌模板包含同源片头/片尾海报、清晰字幕、轻量动画与可选配图。
- 分析结果默认待人工确认；未经用户确认不自动公开发布或投放。

## 十三、风险与应对

| 风险 | 应对方式 |
|---|---|
| ASR 错字导致误判/字幕错误 | 显示置信度和证据、人工校对、低置信段��自动发布 |
| 片段上下文不完整 | 评分加入独立成片性；按句界/乐句扩展；预览显示前后文 |
| 编码不稳定或文件超长 | 先探测和代理转码；分阶段队列；断点上传；失败可续跑 |
| 音乐/肖像授权不明 | 上传声明、许可记录、限制分享、删除与投诉处理 |
| 首尾帧不一致 | 复用同一静态组件和参数；抽帧比较并自动验收 |

## 十四、结论

建议先交付“可审核的自动高光候选 + 可编辑时间线 + HyperFrames 模板渲染”的最小闭环，再逐步提高自动化程度。成片质量的关键不仅是转场和字幕，更是亮点识别准确、片段上下文完整、声音清楚、字幕易读且用户易于审核。HyperFrames 把已确定的剪辑决策稳定地转成可重复渲染的视频。
