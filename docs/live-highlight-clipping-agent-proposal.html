直播高光短视频剪辑智能体
建设与执行方案

基于 HyperFrames 的直播内容理解、亮点筛选与自动化视频生产

适用项目：银发歌唱教育 AI 智能体及其他直播内容场景

文档版本：1.0　|　日期：2026年11月

方案核心：先理解直播内容，识别真正值得传播的高光，再剪辑和包装；HyperFrames 负责可编辑、可复现的视频合成与渲染，不把“套模板”误当成“识别亮点”。片头与片尾海报画面采用同一份静态视觉源，确保首帧和尾帧画面一致。

一、方案摘要

本方案建设一个可执行的直播高光短视频智能体。用户上传直播录像后，系统完成媒体检查、音视频转写、内容分段、焦点识别、高光评分、候选片段审核、字幕与视觉包装、HyperFrames 渲染及成片下载。系统的目标不是把直播机械地切成若干段，而是找到具有明确主题、信息价值、情绪或互动亮点，并且脱离直播上下文仍能看懂的片段。

产品由智能体工作台（前端）、业务 API 与任务编排后端、媒体分析服务、对象存储/数据库、HyperFrames 项目生成与渲染服务构成。模型给出候选与依据，规则负责安全边界和质量门槛，用户可在时间轴上复核、改起止点、改标题和字幕，然后确认渲染。

二、产品目标与设计原则

  • 高光优先：只推荐有明确亮点的内容，不以“每隔固定时长切一刀”作为剪辑逻辑。
  • 可解释：每个推荐片段展示起止时间、内容摘要、亮点类型、评分依据及转写证据。
  • 人机协作：自动生成候选，用户可以接受、排除、合并、拆分、调整入点/出点，未经确认不自动发布。
  • 适合银发歌唱教育：优先发现教师示范、学员进步、唱法纠正前后对比、易懂技巧、答疑互动、集体共鸣和课堂成果。
  • 可复现可编辑：HyperFrames 使用 HTML/CSS/JavaScript 时间线组合，保留项目文件与素材引用，便于重新渲染。
  • 隐私与版权：上传授权、访问控制、保留期限、音乐授权、肖像与声音使用授权均纳入产品流程。

3.2 智能体工作台交互流程

  1. 用户新建项目并上传直播录像；前端显示上传进度、校验结果和预计分析状态。
  2. 分析完成后呈现章节概览与高光候选。每张候选卡显示缩略图、时间范围、推荐标题、内容摘要、类型、总分及分项分数。
  3. 点击候选可播放带时间码的视频并查看对应转写文本。证据不足、音频不清或画面缺失时明确提示，不虚构内容。
  4. 用户挑选候选，设定竖屏/横屏、目标时长、字幕样式、标题和音乐；支持批量应用模板。
  5. 预览后确认渲染。渲染成功后提供 MP4、封面和可选的项目包下载；失败显示可理解的错误与重试入口。

3.3 页面状态与错误处理

任务状态统一为：queued（排队）、uploading（上传中）、analyzing（分析中）、review_required（待审核）、rendering（渲染中）、succeeded（完成）、failed（失败）、cancelled（取消）。长任务用轮询或 Server-Sent Events 推送进度；网络中断后可恢复查看。错误需分为格式不支持、文件损坏、无可用音轨、转写失败、素材缺失、HyperFrames 检查失败、渲染超时等，并给出下一步操作。

  └─ 任务编排服务（队列 / 状态机）
       ├─ 媒体预处理：FFmpeg 探测、抽音频、代理视频、关键帧
       ├─ 内容理解：ASR 转写、说话人/章节、文本与视听事件分析
       ├─ 高光决策：候选生成、评分、去重、时长与上下文校验
       ├─ 剪辑计划：时间码、字幕、标题、画幅适配、模板参数

存储：关系数据库 + 对象存储（原片、代理、缩略图、转写、项目文件、成片）

职责边界：HyperFrames 是 HTML 原生、可逐帧确定性渲染的视频合成/渲染引擎。它负责把已选定的片段、图形、字幕、音乐和动画按时间线渲染；直播语义理解、ASR、亮点判断、素材权限、用户审核和任务管理属于本系统的上游业务能力，不能假设 HyperFrames 自己会判断高光。

五、前端实施设计

5.1 推荐前端模块

采用 React 或 Vue 均可，优先把视频、时间线、任务状态、表单校验拆为独立模块。核心组件包括：上传器（分片/断点续传）、任务状态面板、候选高光卡片、播放器（时间码跳转）、波形与剪辑边界编辑器、字幕编辑表格、模板预览器、渲染任务列表和下载组件。

5.2 前端与后端交互约定

  • 所有业务请求带登录态；项目/任务资源必须做服务端权限校验，不能只依赖前端隐藏按钮。
  • 耗时操作返回 task_id，前端通过事件流或定时查询获取进度；上传采用预签名 URL，避免大文件经业务服务器转发。
  • 时间统一使用原片时间轴的秒（小数），展示为 HH:MM:SS.mmm；裁切服务需处理关键帧与编码误差。
  • 前端编辑只提交差异配置，保留原始 AI 结果，支持撤销/重做与草稿版本。
  • 上传、分析、渲染的每一步展示可取消/重试策略；重复请求使用 Idempotency-Key 防止重复创建任务。

七、后端服务与数据处理

7.1 服务模块

  • 媒体服务：文件探测、校验、代理视频、抽取音频、关键帧与波形；保留原片，不对原始文件做破坏性修改。
  • 转写服务：输出带词级或句级时间戳的文本、语言、置信度；支持人工纠错。
  • 内容理解服务：章节切分、主题归纳、问答/示范/总结等事件识别；涉及情绪时只作为弱信号，不单独决定是否高光。
  • 高光排序服务：结合语义价值、信息完整性、可独立观看性、音视频质量、互动信号、重复度与��险项评分。
  • 剪辑计划服务：将候选时间范围扩展上下文后自动找句界/静音边界，再裁紧；避免截断问题、回答、歌曲乐句或关键动作。
  • HyperFrames 生产服务：从受控模板与 JSON 参数生成项目；执行 CLI 检查、预览/抽帧审核与渲染；记录 CLI 版本和素材哈希。
  • 任务队列：将上传后分析、代理生成、渲染等拆为可重试的幂等任务；设置并发、超时、优先级及失败队列。

7.2 高光评分建议

初期可采用可解释的加权规则，不应宣称模型能准确预知传播效果。建议分项为：主题/知识价值 30%、表达清晰与信息完整 25%、独立成片能力 20%、互动或情绪变化 10%、画面/声音质量 10%、新颖性 5%。重复片段、严重噪声、语义不完整、授权不明属于扣分或阻断条件。通过离线人工标注集评估命中率后再调整权重；教师示范和歌唱表演场景可以配置不同权重。高光分数用于排序，不等于发布保证。

八、HyperFrames 视频包装与交付规范

8.1 视频画面与模板内容

默认社交平台竖屏 9:16、1080×1920、30fps；同时支持 16:9 与 1:1。每条切片可包含：主体直播视频、动态字幕、章节/主题标题、重点词强调、讲师姓名/课程角标、品牌色图形、转场或轻量动画、可选背景音乐、封面海报。画面内容放在安全区域内，字幕对比度足够、字号照顾中老年观看者；不得遮挡口型、乐器或教学动作。

8.2 片头、片尾与首尾帧一致

硬性验收要求：首帧与最后一帧显示同一张海报的同一构图、尺寸、位置、色彩及文字。实现方式为复用同一个静态 poster 图层/素材与相同 CSS 状态，不分别生成两张近似图。片头从海报状态进入内容，片尾从内容回到完全相同的海报状态；最后一帧在动画结束后保留静止海报。
  • 首帧 t=0：完整静态海报（品牌、标题、讲师/课程信息），不加随机或依赖实时网络的内容。
  • 片头：海报停留约 0.5–1.0 秒后，以淡出/缩放/遮罩等轻动画进入切片；动画必须可按时间轴确定性 seek。
  • 主体：高光视频、逐句字幕、必要的强调动画、可选提示图形。
  • 片尾：主体结束后回到与 t=0 完全相同的海报视觉状态；片尾停留约 0.8–1.5 秒，便于识别课程/账号。
  • 音频：片头片尾可配轻音乐与淡入淡出；视觉帧一致是强制要求，音频不必首尾波形相同。音乐须有明确授权；避免掩盖原声与歌唱内容。
  • 验收：用 FFmpeg 抽取首帧与最后一帧进行像素比较；如编码造成少量差异，需在渲染前验证两者来自相同海报状态并设定像素容差，同时人工检查标题、色彩和布局完全一致。

8.3 HyperFrames 工程执行约定

每个输出项目保存根组合、场景组合、素材与渲染参数。时间元素按 HyperFrames 约定声明 class="clip"、data-start、data-duration；每个场景注册暂停时间线，保证渲染可确定性。视频按时间线配置音频属性，音乐使用独立 audio 轨道；素材使用项目内相对路径。渲染前执行 npx hyperframes check --json，处理错误并审查警告；新模板先预览和抽帧检查，再批量生产。不得在组合中依赖网络请求、系统当前时间、非固定随机数或不可 seek 的动画。

8.4 字幕、动画、图画与音乐规则

  • 字幕：逐句同步、标点规范、简体中文；关键词可着色/加粗，但不整屏跳动；字幕应可编辑并导出 SRT/VTT。
  • 动画：字幕入场、标题卡、重点词提示、转场均以时间轴驱动；动画适度、清晰、不造成眩晕。
  • 图画/图形：可用品牌图标、乐谱符号、气息/节奏提示等轻量辅助画面；内容须与讲解一致，不能凭空生成错误乐理信息。
  • 音乐：优先保留教师讲解、歌唱示范原声；BGM 音量自动 ducking，讲解/演唱期间降低或关闭。素材必须记录来源、许可证、用途和有效期。
  • 封面海报：基于首帧/片尾统一设计模板另导出静态封面；标题简短、易读，不能承诺片段中未出现的效果。

十、内容安全、隐私与质量控制

  • 上传时确认用户有权处理直播录像、人物肖像/声音及背景音乐；观众发言和个人信息按最小化原则处理。
  • 下载链接短时有效；按租户隔离对象存储；传输与存储加密；提供删除入口和可核验的删除任务状态。
  • 未成年人、隐私泄露、医疗/财务等敏感内容、诽谤或明显侵权片段可标记为需人工审核或禁止导出。
  • 模型输出保留来源证据和置信度；不得把自动摘要伪装成逐字原话；字幕低置信段显著提示人工校对。
  • 渲染质量检查至少包括：可播放、时长/画幅正确、音画同步、字幕无截断、无黑帧/静帧异常、首尾海报一致、音乐授权记录完整。

十二、建议的 MVP 默认配置

  • 一次处理一条 MP4/MOV 直播录像；先实现中文普通话。
  • 每条直播最多推荐 8 个候选，默认时长 20–60 秒；允许用户另选 15/30/60 秒剪辑目标。
  • 默认输出 9:16、1080×1920、30fps；原声优先、BGM 默认关闭或极低音量，待用户选择有授权的曲库。
  • 采用固定品牌模板，包含同源片头/片尾海报、清晰字幕、轻量动画与可选配图。
  • 分析输出默认“待人工确认”；未经用户确认，不自动公开发布或投放。

十三、风险与应对

风险应对方式
ASR 错字导致亮点误判或字幕错误显示置信度、转写证据与人工校对；关键术语词表；低置信片段不直接自动发布
高光分高但片段上下文不完整评分加入独立成片性；剪辑边界按句子/乐句扩展；预览时显示前后文
直播编码不稳定、超长文件先探测与代理转码；分阶段队列；对象存储分片上传；失败可续跑
音乐、肖像或直播内容授权不明上传声明、素材许可记录、限制下载/分享；提供删除与投诉处理机制
首尾海报看似一致但帧并不相同复用同一静态海报组件及参数；固定根时间线；渲染后抽帧比较并纳入自动化验收

十四、结论

建议先交付“可审核的自动高光候选 + 可编辑时间线 + HyperFrames 模板渲染”的最小闭环，再逐步提高自动化程度。成片质量的关键不只是转场或字幕，而是亮点识别的准确性、片段的上下文完整、歌唱/讲解声音清楚、字幕易读，以及用户能够轻松审核。HyperFrames 用于把这些已确定的剪辑决策稳定地转成可重复渲染的成片。
